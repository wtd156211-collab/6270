# 流式重击者检测（从 0 实现）

起始环境里只有本说明、`samples/**` 与 `.gitignore`：引擎、页面、测试都新写。Python 3.13、只用标准库；
页面是单文件 HTML，无构建无依赖；测试用 unittest。

## 一、范围

做：一个单遍流式重击者检测引擎（库 + 入口 `heavyhitters.py`）：读一行一个键的流，按命令行给的相对
误差 `eps` 报出超过阈值的键及其估计频次、误差界，并把命中渲染成自包含页面 `heavyhitters.html`。

不做：全量精确统计（不许把每个不同键都留在内存里）、回读或 seek 输入、多文件合并与分布式归并、滑动窗口
与时间衰减、写盘中间态与断点续跑、解析键以外的内容、自适应参数、联网、第三方依赖与构建步骤。

## 二、口径与公式

- **流**：`N` = 流文件的行数。`eps = 分子/分母`（`0 < 分子 < 分母`，命令行给），**阈值** `θ = 分子×N/分母`
  （有理数），**误差界上限** `B = ⌊分子×N/分母⌋`。
- **必须报**：精确频次 `f` 满足 `f×分母 > N×分子` 的键一个都不能漏（严格大于；正好等于阈值的不强制）。
- **精度**：每行都要带误差界 `b`，要求 `b ≤ B` 且 `|估计频次 − f| ≤ b`。
- **报出口径**：报出结构里所有 `估计频次 + 误差界 > θ` 的条目，必须报的键必在其中；多余条目允许，但要满足
  同样的精度与规模限制，键必须是流里出现过的键。命中行数不得超过期望文件里的 `命中上限`。
- **精确与估计**：误差界为 0 标 `exact`（估计值就是精确值），大于 0 标 `est`。
- **排序**：估计频次降序；估计频次相同按键的 ASCII 升序。
- **确定性**：同一条命令跑两遍，结果文件与页面逐字节相同；不依赖随机数、系统时钟、哈希随机化与字典遍历
  顺序（阈值、误差界都用整数比，别拿 float 比大小）。

## 三、结构

- 一个键最多一条记录，记录至少含 键 / 估计频次 / 误差界；记录数不许随不同键数增长，只随 `eps` 与常数增长
  （04 号有 59 万个不同键）。
- 不变量：**任意时刻**每条记录都满足 `|估计频次 − 该键此刻的真实频次| ≤ 误差界`，误差界只增不减；这样的键
  只要还在结构里，`估计 + 误差界` 必然超过阈值——零漏检靠的就是「必须报的键一定还在」。
- 一遍扫描：读完即止，不许把行收进 list/dict 再处理，也不许为了重算而回读文件。
- 结构怎么选（摘要表、扣减表、分桶都行）由实现定。

## 四、输入输出与文件格式

本节文件都是 UTF-8（无 BOM）、单 `\n`、末行也有换行。

**4.1 流 `samples/streams/<名>.txt`**：一行一个键，没有空行、注释、表头与分隔符；键匹配
`[a-z0-9][a-z0-9:._-]{0,31}`（纯 ASCII，长度 ≤ 32）。

**4.2 结果文件（引擎写）**

```
H|<流文件名>|N=<总条数>|eps=<分子>/<分母>|B=<误差界上限>|阈值=<分子×N>/<分母>|命中=<行数>|精确=<精确条数>
E|<键>|<估计频次>|<误差界>|<exact|est>
T|命中=<行数>|精确=<精确条数>|估计合计=<Σ估计频次>|误差合计=<Σ误差界>
```

`<流文件名>` 原样取命令行参数；阈值写成不约分的 `分子×N/分母`；E 行按第二节排序、键不重复；没有命中时只有
H、T 两行。

**4.3 期望文件 `samples/expected/<同名>.txt`**

```
H|<名>|N=<总条数>|不同键=<个数>|eps=<分子>/<分母>|B=<误差界上限>|阈值=<分子×N>/<分母>|必须报=<个数>|命中上限=<行数>|尾频=1
E|<键>|<精确频次>|<must|opt>|<估计下限>|<估计上限>
T|条目=<行数>|必须报=<个数>|精确合计=<Σ精确频次>|最大=<最大精确频次>|不同键=<个数>
```

只列精确频次 ≥ 2 的键（按精确频次降序、并列按键升序）；未列出的键一律恰好出现一次（`尾频=1`）。
`估计下限 = max(1, 精确频次 − B)`、`估计上限 = 精确频次 + B`。

**4.4 命令行**

```
python heavyhitters.py run <流文件> <结果文件> --eps <分子>/<分母>
python heavyhitters.py report <结果文件> <页面文件>
```

仓库根目录执行；`heavyhitters.py` 既是库也是入口，公开接口自定（写进模块 docstring）；诊断走 stderr；
退出码 0 跑完，1 表示输入不可用且不写输出文件。

**4.5 页面**：`report` 只读结果文件，不读流、不重算频次。单文件 HTML——样式、数据、脚本全内联，无任何外部
引用（`http(s)`、CDN、本地文件），双击即开，跑两遍逐字节相同。必须内嵌
`<script id="hits" type="text/plain">…</script>`，内容与结果文件（去掉末尾换行）逐字节相同。页面上要有：
① 摘要（总条数、eps、误差界上限、阈值、命中数、其中精确数）；② 排行（按结果文件顺序给出名次、键、估计
频次、误差界，用颜色区分 `exact`/`est` 并写进图例）；③ 每条命中的横条（长度按估计频次，误差界
单独标出）。页面数值只能取自内嵌结果。

## 五、性能与验收口径

规模：05 号 1000 万行 / 20 MB，04 号 60 万行 / 59 万个不同键。

- 单遍：输入只顺序读一遍，不回读、不 seek、不先把所有行收进内存。
- 内存：`run` 峰值分配 ≤ 24 MiB（`tracemalloc` 扣基线），05 号与 04 号一样；`report` ≤ 64 MiB。
- 时间：参考机（本机 CPython、单进程单线程、SSD）05 号 `run` ≤ 30 秒、其余样例与 `report` ≤ 5 秒。
- 对拍（验收方式，逐条可核）：对每份流按 4.4 跑 `run`，与 `samples/expected/<同名>.txt` 比——(1) 每个
  `must` 键都要出现（零漏检）；(2) 每行 键不重复、`估计频次 ≥ 1`、`误差界 ≤ B`、`估计频次 + 误差界 > θ`、
  `exact` 当且仅当误差界为 0，精确频次按期望文件查（未列出的按 `尾频=1`），估计值落在该行区间内；
  (3) 行数 ≤ `命中上限`、E 行顺序符合排序口径、H/T 的计数与 E 行一致。
- 确定性：同一份流跑两遍逐字节相同；`report` 跑两遍逐字节相同。
- 页面：4.5 三项齐全、内嵌内容与结果文件一致。
- 测试：`python -m unittest discover -s tests` 全绿，测试只用标准库、只读 `samples/`，测试自己写。

## 六、样例说明

`samples/streams/<名>.txt` 与 `samples/expected/<名>.txt` 一一对应；括号里是 eps / B / 必须报 / 命中上限。

| 样例 | 条数 | 不同键 | 场景与关键结果 |
| --- | --- | --- | --- |
| `01-long-tail` | 150000 | 67563 | 长尾极长（1/1000，150，5，60）：5 个头部键 3000~40000、24 个中间键 2~149 在阈值下 |
| `02-head-heavy` | 200000 | 105 | 少数键占大头（1/10000，20，5，20）：5 个键占 99.95% |
| `03-near-threshold` | 40001 | 39375 | 频次压在阈值上下（1/1000，40，7，80）：16 个键 32~51，阈值 40.001，41 条才超标 |
| `04-vast-keyset` | 600000 | 593636 | 键基数极大而总量不大（1/1000，600，1，60）：59 万个键各 1 条，只有 `bulk:one` 超标 |
| `05-scale-1e7` | 10000000 | 26 | 千万级（1/10000，1000，12，40）：a~l 超标、`m` 的 977 条在阈值下；性能与内存口径用它 |
| `06-tiny` | 21 | 4 | 极小流（2/7，6，1，10）：阈值正好是整数 6，`b` 的 6 条正好压在阈值上 |

`samples/notes.md` 是现场记录（背景不是规格），有冲突以本文件为准。
