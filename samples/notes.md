# 现场记录

随手记的，回头看能少走点弯路。

- 日志一天十亿条，写进去的多，关心的少：真正要盯的就是出现最多的那几百个键，剩下的都是长尾。
- 之前有人用字典硬存，跑到一半内存就爆了，机器直接 OOM 掉，事后只看得到半份数据。
- 我们要的不是「大概齐」：真正超过阈值的键一个都不能漏，漏一个就算不合格。计数有偏差可以忍，但要有个界，
  界写在 README 里，报告里也得带上。
- 这两条是往两个方向拽的：结构给小了会漏，给大了内存就超。上限写死在 README 里，得自己找平衡。
- 数据是流式的，只能扫一遍，不许回读第二遍；也别把行都攒起来慢慢看，攒起来一样爆。
- 排序也要定死：估计频次一样的按什么次序排，README 里写了。不然两次跑出来的排行不一样，没法对比。
- 报告是给值班的人看的：命中的键按频次排出来，标清楚哪些是确定精确的、哪些是估计值，旁边给误差界。
  数值必须来自引擎，别在报告里重算——上次就是因为报告自己算了一遍，两边对不上，白查了一晚上。
- 交付前对方强调过：同一份流跑两遍，结果文件与页面必须完全一样。
